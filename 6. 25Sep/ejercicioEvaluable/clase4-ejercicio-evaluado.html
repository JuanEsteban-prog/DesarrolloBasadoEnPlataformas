¿Qué vas a construir?

Un ejercicio completo: un simulador de servicio asíncrono con un botón que "carga datos de usuario" desde una función que devuelve una Promise (con una probabilidad de fallar, como una petición de red real), manejado con async/await y un try/catch/finally, además de una clase de error personalizada (ServicioError). Vas a escribir tú mismo cada archivo (index.html, styles.css, script.js) siguiendo el código fuente indicado en cada paso.

A lo largo de la guía encontrarás 10 preguntas de opción múltiple (5 puntos cada una, 50 en total) sobre las líneas de código que acabas de escribir. Puedes responderlas mientras avanzas, pero se califican todas juntas, una sola vez, al final, con el botón "Finalizar práctica y calificar". Después de calificar, tus respuestas quedan bloqueadas — solo tienes un intento.

Este ejercicio cubre únicamente los temas de la Clase 4 (JavaScript moderno ES6+, promesas, async/await y manejo de errores). Para la teoría completa abre clase4-javascript-moderno.html, y para la guía de investigación abierta abre clase4-guia-paso-a-paso.html, ambos en esta misma carpeta.

4Crea la clase de error personalizada

En script.js, escribe:

📄 script.js (parte 1)

class ServicioError extends Error {
  constructor(mensaje) {
    super(mensaje);
    this.name = "ServicioError";
  }
}

ServicioError extiende de la clase Error nativa de JavaScript: hereda su comportamiento (como la propiedad message y la pila de llamadas) y además le da un nombre propio, "ServicioError", para poder distinguirla de otros errores más adelante.

Pregunta 1 (5 pts). En class ServicioError extends Error { constructor(mensaje){ super(mensaje); ... } }, ¿qué hace super(mensaje)?

Pregunta 2 (5 pts). ¿Por qué se creó una clase ServicioError personalizada en vez de usar throw "mensaje de texto"?

5Crea la función que simula el servicio

Agrega, debajo de la clase, en script.js:

📄 script.js (parte 2, agregar)

function obtenerDatosUsuario() {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      const exito = Math.random() > 0.3;
      if (exito) {
        resolve({ usuario: "Ana", rol: "estudiante" });
      } else {
        reject(new ServicioError("No se pudo conectar con el servicio"));
      }
    }, 800);
  });
}

obtenerDatosUsuario devuelve una Promise que, tras 800 milisegundos (simulando el tiempo de una petición real), se resuelve con los datos del usuario el 70% de las veces, o se rechaza con un ServicioError el otro 30%.

Pregunta 3 (5 pts). new Promise((resolve, reject) => {...}) — ¿qué representa un Promise?

Pregunta 4 (5 pts). setTimeout(() => {...}, 800) dentro de la Promise — ¿para qué se usa aquí?

6Toma las referencias del DOM y arma el manejador

Agrega, debajo de la función, en script.js (todavía sin el try/catch, lo completas en el próximo paso):

📄 script.js (parte 3, agregar)

const boton = document.getElementById("btnCargar");
const resultado = document.getElementById("resultado");

boton.addEventListener("click", async () => {
  resultado.textContent = "Cargando...";
});

Guarda y recarga: al hacer clic en el botón, el texto debe cambiar a "Cargando..." (por ahora se queda ahí, porque todavía no llamamos a obtenerDatosUsuario()).

Pregunta 5 (5 pts). ¿Qué pasa si intentas reasignar una variable declarada con const (como boton o resultado)?

Pregunta 6 (5 pts). Sobre la arrow function async () => {...} usada como manejador de clic, ¿cuál es su principal diferencia con una función tradicional en este contexto?

7Completa el manejador con try/catch/finally

Reemplaza el bloque anterior por esta versión completa, agregando await, el try/catch y el finally:

📄 script.js (parte 3, versión final)

boton.addEventListener("click", async () => {
  resultado.textContent = "Cargando...";
  try {
    const datos = await obtenerDatosUsuario();
    resultado.textContent = `Bienvenido, ${datos.usuario} (${datos.rol})`;
  } catch (error) {
    resultado.textContent = `Error: ${error.message}`;
  } finally {
    console.log("Intento de carga finalizado");
  }
});

Guarda, recarga y haz clic varias veces en el botón: aproximadamente 7 de cada 10 veces verás el mensaje de bienvenida, y las otras verás el mensaje de error — en ambos casos, revisa la consola (F12) y confirma que ves "Intento de carga finalizado" cada vez.

Pregunta 7 (5 pts). En el template literal `Bienvenido, ${datos.usuario} (${datos.rol})`, ¿qué logra la sintaxis ${...}?

Pregunta 8 (5 pts). await obtenerDatosUsuario() dentro de una función async — ¿qué logra await?

Pregunta 9 (5 pts). ¿Qué captura el bloque catch (error) en este código?

Pregunta 10 (5 pts). ¿Qué garantiza que el bloque finally se ejecute?
